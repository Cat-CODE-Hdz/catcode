# APROBACIÓN — PROCESO Y REGLAS

**Parte del flujo de producción (paso 11).**
**Plazos:** Landing/CUSTOM 72h · Contenido semanal 48h.

---

## Modalidades de aprobación (multi-aprobador)

| Modalidad | Quién aprueba | Cuándo |
|---|---|---|
| Solo yo | CEO | Proyectos estándar, cliente con poca fricción |
| Yo + otro | CEO + responsable (Frontend/Social) | Landing importante, cliente exigente |
| Solo otro | Un miembro del equipo | Cuando CEO no está disponible (delegado) |

La modalidad se fija en el onboarding del cliente (08_PLANTILLAS/ONBOARDING).

## Plazos

- **Landing / CUSTOM:** el cliente dispone de **72 horas** hábiles para aprobar o pedir cambios.
- **Contenido semanal:** **48 horas** antes de la fecha de publicación objetivo.
- Si no hay respuesta en plazo: se intenta contacto por 2 canales (email + WhatsApp). Si sigue sin respuesta, se procede a publicar la versión entregada marcándola como "APROBADO implícito" salvo que el cliente active el plan de que "nada se publica sin revisión".

## Frase clave

> Para aprobar, el cliente confirma con la palabra **"APROBADO"** (en el medio pactado: email, WhatsApp o panel).

## Qué cuenta como aprobación

- Texto literal "APROBADO" (recomendado) o confirmación explícita equivalente: "todo bien", "dale", "ok publica".
- Silencio NO es aprobación salvo el caso de aprobación implícita del plazo.

## Cambios tras aprobación

- Cambio menor (color, texto de 1 frase): se aplica sin costo, se hace en la siguiente versión si la publicación ya está lista.
- Cambio de alcance (nueva sección, nueva página, más piezas): se registra en `00_REGISTRO` y cotiza aparte (ver REGLAS_COMERCIALES).
- Todo cambio queda documentado para trazabilidad.

## Registro

- En la carpeta del cliente, versión del deliverable: `_v01`, `_v02`… y `_FINAL` al aprobar (DOCUMENTO 16).
- No usar "final-final", "FINAL2" ni "definitivo definitivo".
